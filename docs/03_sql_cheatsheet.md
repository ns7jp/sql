# 03. SQL早見表（チートシート）

演習中に「あれ、どう書くんだっけ？」となったときに見返すための一覧です。
暗記帳としても使えるように、覚え方のコツもあわせて記載しています。

## 1. SELECT文は「書く順番」と「実行される順番」が違う

これがSQL初心者が最初につまずくポイントです。**書く順番**と、
データベースが実際に**処理する順番**は異なります。

| 書く順番 | 句 | 実行される順番 | 何をするか |
|---|---|---|---|
| 1 | `SELECT` | 5番目 | 表示する列を決める |
| 2 | `FROM` | 1番目 | どのテーブルを使うか決める |
| 3 | `JOIN ... ON` | 2番目 | 他のテーブルと結合する |
| 4 | `WHERE` | 3番目 | 行（レコード）を絞り込む |
| 5 | `GROUP BY` | 4番目 | 行をグループにまとめる |
| 6 | `HAVING` | 5番目 | グループを絞り込む |
| 7 | `ORDER BY` | 6番目 | 並び替える |
| 8 | `LIMIT` | 7番目 | 件数を制限する |

> 💡 **覚え方**：データベースはまず「どのテーブルから(FROM)」「どう結合して(JOIN)」
> 「どの行を(WHERE)」「どうグループ化して(GROUP BY)」「どのグループを残すか(HAVING)」を決めてから、
> 最後に「どの列を見せるか(SELECT)」「どう並べるか(ORDER BY)」を決める、という順番です。
> **「WHEREは1行ずつの条件」「HAVINGはグループ化した後の条件」**という違いを混同しないことが重要です。

## 2. 比較演算子・条件

| 演算子 | 意味 | 例 |
|---|---|---|
| `=` | 等しい | `salary = 500000` |
| `<>` または `!=` | 等しくない | `status <> 'キャンセル'` |
| `>` `>=` `<` `<=` | 大小比較 | `price >= 1000` |
| `BETWEEN a AND b` | a以上b以下の範囲 | `price BETWEEN 1000 AND 5000` |
| `IN (a, b, c)` | いずれかに一致 | `prefecture IN ('東京都', '大阪府')` |
| `LIKE` | あいまい一致（`%`は0文字以上、`_`は1文字） | `employee_name LIKE '%田%'` |
| `IS NULL` / `IS NOT NULL` | NULLかどうか | `employee_id IS NULL` |
| `AND` / `OR` / `NOT` | 条件の組み合わせ | `a AND (b OR c)` |

> 💡 **覚え方**：NULLは「値が無い」という特別な状態なので、`= NULL` では判定できません。
> 必ず `IS NULL` / `IS NOT NULL` を使います。

## 3. 集計関数

| 関数 | 意味 |
|---|---|
| `COUNT(*)` | 行数を数える（NULLも数える） |
| `COUNT(列名)` | その列がNULLでない行数を数える |
| `SUM(列名)` | 合計 |
| `AVG(列名)` | 平均 |
| `MAX(列名)` / `MIN(列名)` | 最大値 / 最小値 |

> 💡 **覚え方**：`COUNT(*)`と`COUNT(列名)`は結果が異なることがあります。
> 対象の列にNULLが含まれる場合は必ず結果を見比べてみましょう。

## 4. JOIN（結合）の種類

```text
INNER JOIN … 両方のテーブルに一致する行だけを残す
   A ∩ B （AとBの共通部分のみ）

LEFT JOIN  … 左（先に書いた）テーブルは全件残し、
             右テーブルに一致がなければ NULL で埋める
   A の全件 + 一致した B の情報

自己結合（self join） … 同じテーブルを2回登場させて結合する
             （例：社員テーブルを「本人」と「上司」として2回使う）
```

| 書き方 | 使いどころ |
|---|---|
| `INNER JOIN` | 両方に対応するデータがある行だけ見たいとき |
| `LEFT JOIN` | 「対応するデータが無い行」も含めて見たい、または「無いものを探したい」とき |
| `テーブルA AS a, テーブルA AS b` + `WHERE a.x = b.y` | 自己結合。同じテーブルに別名(AS)をつけて区別する |

> 💡 **覚え方**：「一致しないものを探したい」→ `LEFT JOIN` して `WHERE 右テーブルの列 IS NULL`、
> という組み合わせは実務でも頻出のパターンです（[レベル3](../exercises/level3_join.md)で扱います）。

## 5. サブクエリ（クエリの中のクエリ）

| 書く場所 | 例 | 意味 |
|---|---|---|
| `WHERE` 句 | `WHERE salary > (SELECT AVG(salary) FROM employees)` | 条件の一部として使う |
| `WHERE ... IN (...)` | `WHERE customer_id IN (SELECT customer_id FROM orders)` | 複数の値のリストとして使う |
| `WHERE EXISTS (...)` | 相関サブクエリと組み合わせて「〜が存在する行」を探す | 存在チェック |
| `FROM` 句 | `FROM (SELECT ... ) AS sub` | 一度集計した結果をさらに絞り込む |
| `SELECT` 句 | `SELECT ..., (SELECT AVG(...) ...) AS avg_x` | 1行1値を追加の列として表示する |

## 6. データ操作（DML）とトランザクション

| 文 | 意味 |
|---|---|
| `INSERT INTO テーブル (列...) VALUES (値...)` | 行を追加する |
| `UPDATE テーブル SET 列 = 値 WHERE 条件` | 行を更新する（**WHEREを忘れると全件が更新される**） |
| `DELETE FROM テーブル WHERE 条件` | 行を削除する（**WHEREを忘れると全件が削除される**） |
| `BEGIN` （または `START TRANSACTION`） | ここから一連の変更をひとまとめにする、と宣言する |
| `COMMIT` | ここまでの変更を確定する |
| `ROLLBACK` | ここまでの変更を取り消して、変更前の状態に戻す |

> ⚠️ **絶対に覚えておくこと**：`UPDATE`・`DELETE` を書くときは、
> **先に同じ条件で `SELECT` を実行して、対象の行数・内容を確認してから**実行する習慣をつけましょう。
> 本番のサーバーで `WHERE` 句を書き忘れると、全件を上書き・削除してしまう重大な事故につながります。

## 7. よくあるエラーと原因

| エラーメッセージ（例） | よくある原因 |
|---|---|
| `Unknown column 'xxx' in 'field list'` | 列名のスペルミス、または別のテーブルの列を参照している |
| `Table 'xxx' doesn't exist` | テーブル名のスペルミス、`db/schema.sql`が実行されていない |
| `You have an error in your SQL syntax` | カンマの付け忘れ・余分なカンマ、キーワードのスペルミス、括弧の閉じ忘れ |
| `Column 'xxx' in field list is ambiguous` | JOINした複数テーブルに同じ名前の列があり、どちらか指定していない（`テーブル名.列名`で指定する） |
