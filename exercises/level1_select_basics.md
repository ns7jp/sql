# レベル1: SELECTの基本

> 🎯 このレベルで身につくこと
> - `SELECT` 文の基本構造（何を・どこから取得するか）
> - 表示する列を選んだり、見やすい別名（AS）を付ける方法
> - `WHERE` 句を使った条件絞り込みと、比較演算子・`AND`/`OR`・`LIKE`・`BETWEEN`・`IN` の使い分け
> - `NULL`（値が存在しない状態）の正しい扱い方
> - `ORDER BY`・`LIMIT`・`DISTINCT` によるデータの整形

## 使用するテーブル

このレベルでは主に、社員情報を管理する `employees`（社員）テーブルと、商品情報を管理する `products`（商品）テーブルを使います。どちらも「1つのテーブルだけを見れば答えがわかる」シンプルな構造なので、SELECT文の基本を練習するのに最適です。テーブルの列構成や他テーブルとの関係を詳しく知りたい場合は、[docs/01_schema.md](../docs/01_schema.md) のER図を参照してください。

## 問題 1: 全件表示とSELECT文の基本構造

**目的**: `SELECT * FROM テーブル名;` という、SQLで最も基本となる文の形を覚える。

**問題文**:
社員（employees）テーブルに登録されている、すべての社員の全列のデータを表示してください。並び順の指定は不要です。

<details>
<summary>💡 ヒントを見る</summary>

- SQLは「`SELECT` 何を」「`FROM` どこから」の順に書きます。
- 「すべての列」を表す記号は `*`（アスタリスク）です。
- 文の最後は必ずセミコロン（`;`）で終えます。

</details>

<details>
<summary>✅ 模範解答と解説を見る</summary>

**模範解答**:

```sql
SELECT * FROM employees;
```

**実行結果イメージ**:

```text
+-------------+---------------+---------------+----------+------------+--------+------------+
| employee_id | employee_name | department_id | position | hire_date  | salary | manager_id |
+-------------+---------------+---------------+----------+------------+--------+------------+
|           1 | 山田 太郎      |             1 | 部長     | 2015-04-01 | 650000 |       NULL |
|           2 | 佐藤 花子      |             2 | 部長     | 2014-04-01 | 680000 |       NULL |
|           3 | 鈴木 一郎      |             3 | 部長     | 2016-04-01 | 600000 |       NULL |
|           4 | 高橋 次郎      |             1 | 課長     | 2017-04-01 | 520000 |          1 |
...
（全12件）
+-------------+---------------+---------------+----------+------------+--------+------------+
```

**解説**:
`SELECT * FROM employees;` は「`employees` テーブルの、すべての列・すべての行を表示する」という意味です。`*` は「全部」を表す特別な記号で、テーブルにどんな列があるか分からないときの確認にもよく使います。結果は `employees` テーブルを作成したときの列の並び順（`employee_id`, `employee_name`, `department_id`, `position`, `hire_date`, `salary`, `manager_id`）で表示される点も覚えておきましょう。SQL文の末尾には必ずセミコロン `;` を付けます。忘れても動く場合がありますが、複数の文を続けて書くときに区切りが分からなくなるため、習慣として必ず付けるようにしてください。

**覚え方のポイント**:
`SELECT * FROM 表の名前;` は「表の名前という表から、全部持ってきて」という英語の語順そのままだと考えると覚えやすいです。実務では `*` は動作確認やデバッグでは便利ですが、本番のプログラムでは「必要な列だけを指定する」書き方（問題2で学びます）を使うのが基本です。

</details>

## 問題 2: 表示する列を選ぶ

**目的**: 必要な列だけを指定して取得する方法と、`AS` を使って列に分かりやすい別名を付ける方法を覚える。

**問題文**:
商品（products）テーブルから、「商品名」「価格」「在庫数」の3つの列だけを取得してください。それぞれの列には `AS` を使って `商品名`・`価格`・`在庫数` という見出し（別名）を付けてください。並び順の指定は不要です。

<details>
<summary>💡 ヒントを見る</summary>

- 複数の列を取得したいときは、列名を `,`（カンマ）で区切って並べます。
- 列名の後ろに `AS 別名` と書くと、結果に表示される見出しを変えられます。
- `products` テーブルの列名は `product_name`（商品名）、`price`（価格）、`stock_quantity`（在庫数）です。

</details>

<details>
<summary>✅ 模範解答と解説を見る</summary>

**模範解答**:

```sql
SELECT product_name AS 商品名, price AS 価格, stock_quantity AS 在庫数
FROM products;
```

**実行結果イメージ**:

```text
+--------------------+--------+--------+
| 商品名              | 価格   | 在庫数 |
+--------------------+--------+--------+
| ノートパソコン       |  89800 |     15 |
| ワイヤレスイヤホン    |  12800 |     40 |
| 電気ケトル           |   4980 |     25 |
...
（全16件）
+--------------------+--------+--------+
```

**解説**:
`SELECT` の後ろに列名をカンマ区切りで書くと、その列だけを取り出せます。問題1の `SELECT *` との違いは、「必要な情報だけに絞れる」ことです。実務では、テーブルに何十個も列があることが珍しくないため、使わない列まで取得するのは無駄な処理になります。`AS` は列の見出し（エイリアス）を付ける命令で、`price AS 価格` のように書くと、結果の見出しが `price` ではなく `価格` になります。もとの `products` テーブルの列名自体が変わるわけではない点に注意してください。

**覚え方のポイント**:
`AS` は「〜として」という意味の英単語そのままなので、「`price` を `価格` として表示する」と読み替えると理解しやすいです。実は `AS` は省略して `price 価格` のように書くこともできますが、初心者のうちは `AS` を書いたほうが「これは別名を付けている」と意図が伝わりやすく、読みやすいコードになります。

</details>

## 問題 3: 条件で絞り込む

**目的**: `WHERE` 句と比較演算子（`>=` など）を使って、条件に合う行だけを取得する方法を覚える。

**問題文**:
社員（employees）テーブルから、給与（salary）が50万円（500000）以上の社員を、「社員名」「部署ID」「給与」の3列で表示してください。並び順の指定は不要です。

<details>
<summary>💡 ヒントを見る</summary>

- 条件を指定するときは `FROM テーブル名` の後ろに `WHERE 条件` を書きます。
- 「以上」を表す比較演算子は `>=` です（`>` は「より大きい」で50万円ちょうどの人が含まれなくなるので注意）。
- 取得したい列は `employee_name`, `department_id`, `salary` です。

</details>

<details>
<summary>✅ 模範解答と解説を見る</summary>

**模範解答**:

```sql
SELECT employee_name, department_id, salary
FROM employees
WHERE salary >= 500000;
```

**実行結果イメージ**:

```text
+---------------+---------------+--------+
| employee_name | department_id | salary |
+---------------+---------------+--------+
| 山田 太郎      |             1 | 650000 |
| 佐藤 花子      |             2 | 680000 |
| 鈴木 一郎      |             3 | 600000 |
| 高橋 次郎      |             1 | 520000 |
| 渡辺 健太      |             2 | 540000 |
| 加藤 綾        |             4 | 500000 |
+---------------+---------------+--------+
6 rows in set
```

**解説**:
`WHERE` 句はSQLの中でも特に重要な部分で、「どの行を取得するか」の条件を指定します。今回使った `>=` は「以上」を意味する比較演算子で、他にも `<=`（以下）、`>`（より大きい）、`<`（より小さい）、`=`（等しい）、`<>` または `!=`（等しくない）があります。ポイントは、境界値（今回なら500000ちょうど）を含めるかどうかで演算子を使い分けることです。加藤さんの給与はちょうど500000円ですが、`>=` を使っているので結果に含まれています。もし `>` を使っていたら、加藤さんは除外されてしまいます。

**覚え方のポイント**:
不等号の向きは数学と同じなので直感的に覚えられますが、「イコールが付いているかどうか」で結果の1件が変わることを意識しましょう。実務でも「50万円以上」なのか「50万円より多い」なのかは仕様として非常に重要な違いになるため、問題文の日本語を注意深く読む癖をつけてください。

</details>

## 問題 4: 複数条件を組み合わせる

**目的**: `AND`・`OR` で複数の条件を組み合わせる方法と、カッコ `()` で優先順位を明確にする重要性を理解する。

**問題文**:
社員（employees）テーブルから、「営業部（department_id = 1）またはマーケティング部（department_id = 4）に所属していて、かつ役職（position）が『一般』である社員」を、「社員名」「部署ID」「役職」の3列で表示してください。並び順の指定は不要です。

<details>
<summary>💡 ヒントを見る</summary>

- 「どちらか一方」は `OR`、「両方とも満たす」は `AND` で条件をつなぎます。
- `AND` は `OR` より先に評価されるルールがあるため、「(部署Aまたは部署B) かつ 一般」を意図通りに書くには `()` で `OR` の部分をくくる必要があります。
- カッコを付け忘れると、意図と違う結果になることがあるので注意しましょう。

</details>

<details>
<summary>✅ 模範解答と解説を見る</summary>

**模範解答**:

```sql
SELECT employee_name, department_id, position
FROM employees
WHERE (department_id = 1 OR department_id = 4) AND position = '一般';
```

**実行結果イメージ**:

```text
+---------------+---------------+----------+
| employee_name | department_id | position |
+---------------+---------------+----------+
| 田中 三郎      |             1 | 一般     |
| 伊藤 陽子      |             1 | 一般     |
| 吉田 拓也      |             4 | 一般     |
+---------------+---------------+----------+
3 rows in set
```

**解説**:
このSQLの肝は「カッコを付ける理由」です。SQLでは `AND` が `OR` よりも優先して評価されるため、もしカッコなしで `WHERE department_id = 1 OR department_id = 4 AND position = '一般'` と書いてしまうと、実際には `department_id = 1 OR (department_id = 4 AND position = '一般')` という意味になってしまいます。これでは「営業部の全員（役職を問わず）」＋「マーケティング部の一般社員」が対象になり、意図と異なる結果になります。`(department_id = 1 OR department_id = 4)` とカッコでくくることで、「部署の条件」をひとまとまりとして先に評価させ、その結果に対して `AND position = '一般'` を適用できます。

**覚え方のポイント**:
複数の `AND` と `OR` が混ざる条件式では、「どちらの条件をひとまとめにしたいか」を日本語で整理してから、その単位ごとにカッコを付けると間違えにくくなります。迷ったら「カッコを付けすぎて減点されることはない」くらいの気持ちで、意図を明確にするためにカッコを積極的に使いましょう。

</details>

## 問題 5: あいまい検索

**目的**: `LIKE` とワイルドカード（`%`, `_`）を使って、文字列の一部が一致する行を検索する方法を覚える。

**問題文**:
社員（employees）テーブルから、社員名（employee_name）に「田」という文字を含む社員を、「社員名」「部署ID」の2列で表示してください。並び順の指定は不要です。

<details>
<summary>💡 ヒントを見る</summary>

- 文字列の「部分一致」検索には `LIKE` 演算子を使います。
- `%` は「0文字以上の任意の文字列」を表すワイルドカードです。前後に付けると「その文字を含む」という意味になります。
- ちなみに `_`（アンダースコア）は「任意の1文字」を表すワイルドカードで、`%` とは意味が異なります。

</details>

<details>
<summary>✅ 模範解答と解説を見る</summary>

**模範解答**:

```sql
SELECT employee_name, department_id
FROM employees
WHERE employee_name LIKE '%田%';
```

**実行結果イメージ**:

```text
+---------------+---------------+
| employee_name | department_id |
+---------------+---------------+
| 山田 太郎      |             1 |
| 田中 三郎      |             1 |
| 吉田 拓也      |             4 |
+---------------+---------------+
3 rows in set
```

**解説**:
`LIKE '%田%'` は「前後にどんな文字が何文字あってもいいので、途中に『田』を含む」という条件です。`%` を「田」の前後どちらにも付けているのがポイントで、前だけに付けると「田で終わる」、後ろだけに付けると「田で始まる」という意味に変わります。結果を見ると、「山`田` 太郎」「`田`中 三郎」「吉`田` 拓也」のように、名字の前・後ろ・真ん中のどの位置に「田」があっても一致していることが確認できます。なお `_` は1文字だけにマッチするワイルドカードで、例えば `'山_'` は「山」の後に1文字だけ続く2文字の文字列にマッチします（`%` のように文字数が変動する場合には使えません）。

**覚え方のポイント**:
`%` は「なんでもいい・何文字でもいい」という広い網、`_` は「1文字だけ」という狭いスポットだとイメージすると区別しやすいです。実務では、`LIKE '%キーワード%'` の形（前後に%を付ける）が最もよく使われるパターンなので、まずはこの形を覚えておくと応用が効きます。

</details>

## 問題 6: 範囲とリストで絞り込む

**目的**: `BETWEEN` で数値の範囲を、`IN` で複数の候補値を、それぞれ簡潔に指定する方法を覚える。

**問題文**:
社員（employees）テーブルから、「給与（salary）が35万円（350000）から60万円（600000）までの範囲内」で、かつ「営業部（department_id = 1）またはマーケティング部（department_id = 4）に所属している」社員を、「社員名」「部署ID」「給与」の3列で表示してください。並び順の指定は不要です。

<details>
<summary>💡 ヒントを見る</summary>

- 「〇〇から△△まで」という範囲指定には `BETWEEN 下限 AND 上限` が使えます。両端の値を含む点に注意しましょう。
- 「複数の候補のどれか」という条件には `IN (値1, 値2, ...)` が使えます。`department_id = 1 OR department_id = 4` と書くのと同じ意味になります。
- 2つの条件は `AND` でつなぎます。

</details>

<details>
<summary>✅ 模範解答と解説を見る</summary>

**模範解答**:

```sql
SELECT employee_name, department_id, salary
FROM employees
WHERE salary BETWEEN 350000 AND 600000
  AND department_id IN (1, 4);
```

**実行結果イメージ**:

```text
+---------------+---------------+--------+
| employee_name | department_id | salary |
+---------------+---------------+--------+
| 高橋 次郎      |             1 | 520000 |
| 田中 三郎      |             1 | 380000 |
| 伊藤 陽子      |             1 | 360000 |
| 加藤 綾        |             4 | 500000 |
| 吉田 拓也      |             4 | 370000 |
+---------------+---------------+--------+
5 rows in set
```

**解説**:
`BETWEEN 350000 AND 600000` は `salary >= 350000 AND salary <= 600000` と書くのと全く同じ意味ですが、範囲指定であることが一目で分かる書き方です。両端の値（350000円ちょうど、600000円ちょうど）も条件に含まれる点を覚えておきましょう。一方 `IN (1, 4)` は `department_id = 1 OR department_id = 4` の短縮形です。候補が2〜3個ならどちらで書いても大差ありませんが、候補が5個・10個と増えるほど `IN` のほうが読みやすくなります。山田さん（給与650000円）は範囲の上限を超えているため、営業部であっても結果から除外されている点も確認してみてください。

**覚え方のポイント**:
`BETWEEN` は「範囲（連続した値）」、`IN` は「リスト（飛び飛びの値）」に使う、と使い分けを整理すると覚えやすいです。`OR` を何個も並べて書きそうになったときは、「これは `IN` で書き直せないか」と考える癖をつけると、SQLがぐっと読みやすくなります。

</details>

## 問題 7: NULLを扱う

**目的**: 「値が存在しない」ことを表す `NULL` を、`IS NULL` / `IS NOT NULL` で正しく判定する方法を理解する。

**問題文**:
社員（employees）テーブルには、上司の社員IDを表す `manager_id` という列があります。この `manager_id` が設定されていない（＝上司がいない）社員を、「社員名」「部署ID」「役職」の3列で表示してください。並び順の指定は不要です。

<details>
<summary>💡 ヒントを見る</summary>

- 「値が空である」ことを判定するには `IS NULL` を使います。`= NULL` とは書けません。
- 逆に「値が入っている」ことを判定したい場合は `IS NOT NULL` を使います。
- 対象の列は `manager_id` です。

</details>

<details>
<summary>✅ 模範解答と解説を見る</summary>

**模範解答**:

```sql
SELECT employee_name, department_id, position
FROM employees
WHERE manager_id IS NULL;
```

**実行結果イメージ**:

```text
+---------------+---------------+----------+
| employee_name | department_id | position |
+---------------+---------------+----------+
| 山田 太郎      |             1 | 部長     |
| 佐藤 花子      |             2 | 部長     |
| 鈴木 一郎      |             3 | 部長     |
| 加藤 綾        |             4 | 課長     |
+---------------+---------------+----------+
4 rows in set
```

**解説**:
`NULL` は「0」や「空文字」とは違い、「そもそも値が存在しない・未設定である」ことを表す特別な状態です。そのため、他の値との比較でよく使う `=`（イコール）を使って `WHERE manager_id = NULL` と書いても、常に結果が得られません（エラーにはなりませんが、0件になってしまいます）。これは「NULLは何と比較しても『分からない』という結果になる」というSQLのルールによるものです。NULLかどうかを判定するときは、専用の `IS NULL`（NULLである）・`IS NOT NULL`（NULLでない）を使う必要があります。結果を見ると、山田・佐藤・鈴木の3名は各部署の部長で上司がいないのは想像しやすいですが、マーケティング部の課長である加藤さんも `manager_id` が `NULL` です。これはシードデータのコメントにもある通り、マーケティング部には部長職がいないという設定のためです。

**覚え方のポイント**:
「NULL は `=` で捕まえられない、`IS` でしか捕まえられない」と丸ごと覚えてしまいましょう。実務でも「`WHERE 列 = NULL` と書いたのに0件しか返ってこない」はSQL初心者が非常によくハマる間違いなので、最初にここでしっかり体験しておくと後で防げます。

</details>

## 問題 8: 並び替え・件数制限・重複除去

**目的**: `ORDER BY` で並び順を、`LIMIT` で取得件数を、`DISTINCT` で重複除去を、それぞれ指定する方法を覚える。

**問題文**:
商品（products）テーブルには、商品ごとにカテゴリID（category_id）が設定されています。このテーブルに登場するカテゴリIDを重複なく取得し、カテゴリIDの小さい順に並べ替えたうえで、先頭から3件だけ表示してください。

<details>
<summary>💡 ヒントを見る</summary>

- 重複を取り除いて表示するには、`SELECT` の直後に `DISTINCT` を付けます。
- 並び順を指定するには `ORDER BY 列名` を使います。小さい順（昇順）は既定の動作なので `ASC` は省略できます。
- 取得する件数を制限するには、文の最後に `LIMIT 件数` を付けます。

</details>

<details>
<summary>✅ 模範解答と解説を見る</summary>

**模範解答**:

```sql
SELECT DISTINCT category_id
FROM products
ORDER BY category_id
LIMIT 3;
```

**実行結果イメージ**:

```text
+-------------+
| category_id |
+-------------+
|           1 |
|           2 |
|           3 |
+-------------+
3 rows in set
```

**解説**:
`products` テーブルには16件の商品データがあり、`category_id` の値は 1〜5 のいずれかが何度も繰り返し登場します（例えば `category_id = 1` の家電カテゴリだけで4商品あります）。`DISTINCT` を付けずに `SELECT category_id FROM products;` を実行すると16行すべてが表示されてしまいますが、`SELECT DISTINCT category_id` とすることで、同じ値をまとめて「1〜5の5種類しかない」ということが分かります。`ORDER BY category_id` は結果を `category_id` の昇順（小さい順）に並べ替え、最後の `LIMIT 3` は「並べ替えた結果の先頭から3件だけ」を表示する指定です。この3つの句は `SELECT ... FROM ... ORDER BY ... LIMIT ...` の順番で書くというSQLの文法上のルールがあるため、順序を入れ替えるとエラーになります。

**覚え方のポイント**:
`ORDER BY` は必ず `WHERE` より後、`LIMIT` は必ず一番最後、という書く順番をセットで覚えてください。また `DISTINCT` は「列の組み合わせ全体」に対して重複を取り除く点にも注意が必要です（複数列を指定した場合、その複数列の値の組み合わせが完全に一致する行だけがまとめられます）。大きい順に並べ替えたい場合は `ORDER BY category_id DESC` のように `DESC` を付ける、という点も合わせて覚えておくと応用が効きます。

</details>

## この章のまとめ

- `SELECT 列名 FROM テーブル名;` がSQLの基本形。列を `*` にすると全列、カンマ区切りにすると複数列を選べる。
- `AS` を使うと、結果に表示される列の見出しを分かりやすい別名に変更できる。
- `WHERE` 句で条件を指定すると、条件に合う行だけに絞り込める。比較演算子（`=`, `>=`, `<>` など）は境界値を含むかどうかに注意。
- `AND`／`OR` で条件を組み合わせるときは、意図した優先順位になるよう `()` で明示することが大切。
- `LIKE` と `%`・`_` を使うと、文字列の部分一致・あいまい検索ができる。
- `BETWEEN` は連続した範囲、`IN` は飛び飛びの候補リストの指定に向いている。
- `NULL`（値が存在しない状態）は `= NULL` では判定できず、`IS NULL` / `IS NOT NULL` を使う必要がある。
- `ORDER BY` で並び替え、`LIMIT` で件数制限、`DISTINCT` で重複除去ができ、これらは `SELECT ... FROM ... WHERE ... ORDER BY ... LIMIT ...` という決まった順番で書く。

次のレベル2では、複数のテーブルをまたいだ集計（`GROUP BY` や `JOIN` の基礎）など、より実践的な検索方法を学んでいきます。
